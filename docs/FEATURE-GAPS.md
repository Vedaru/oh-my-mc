# 功能对照：其它启动器有、我们没有的

这份表只列**核实过**的差距：每一项都在本仓库里查过实现，没查到才算「缺」。参照对象是
PCL2（Windows 主流）、Prism / MultiMC（跨平台社区标准）、HMCL（第三方认证最全）和
Axolotl / Modrinth App（本项目主要参照）。

状态说明：**有** = 能用的实现；**半** = 有基础设施、UI 或闭环缺一半；**缺** = 查不到。

## 账户与身份

| 功能 | PCL2 | Prism | HMCL | Axolotl | 我们 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| 离线账户（改名即换身份） | 有 | 有 | 有 | 有 | **半** | 只有 `AppSettings.playerName` 一个名字，没有「账户」这个概念：不能存多个身份，也没有 UUID 派生 |
| 微软登录（OAuth 设备码） | 有 | 有 | 有 | 有 | **缺** | 需要 Azure client id，代码里没有任何 auth 模块；`launch_factory` 只透传 `--accessToken` |
| 第三方认证（authlib-injector / Yggdrasil） | 有 | 有 | 有 | 部分 | **缺** | 这条**不需要注册任何凭据**：给定 API 根地址就能登录，是账户体系里最容易先落地的一环 |
| 多账户并存与切换 | 有 | 有 | 有 | 有 | **缺** | 与上一条同一套模型 |
| 皮肤查看 / 更换 / 离线皮肤 | 有 | 有 | 有 | 有 | **缺** | 无 `skin` 模块；设置里没有外观身份相关项 |

## 建议的顺序

按「用户感知 ÷ 成本」和「是否被外部凭据卡住」排：

1. **账户体系（离线多账户 + authlib-injector 第三方认证）** — 不依赖任何注册，能把「只有一个名字」升级成真正的账户，也为将来的微软登录留好模型。
2. **直接加入服务器（`--server/--port`）** — 服务器页已经有地址，加两个启动参数就闭环；顺带做服务器收藏。
3. **整合包目录 + 一键安装**（`project_type:modpack`，装着走现有 `.mrpack` 导入路径），并在导入时记下来源项目/版本，才能谈整合包更新。
4. **资源包 / 光影的更新检查** — 复用模组那套 sha1 认领，成本低。
5. **实例分组 / 备注 / 图标、截图浏览、世界复制与游戏规则** — 体验补齐，无外部依赖。
6. **日志分享、崩溃报告导出、托盘与单实例、快捷键、快捷启动、便携模式** — 工程化与桌面集成。
7. **CurseForge、微软登录、实验室** — 需要 API key / client id / 独立立项，排在最后。

已经做完、不再列进差距的：版本安装（原版 / Fabric / Quilt / Forge / NeoForge）、断点续装、Java 探测与自供、镜像测速换源、联机（LAN + UPnP）、崩溃诊断、模组安装与更新、世界备份还原、内容页分区分页、壁纸与主题、中英双语。
